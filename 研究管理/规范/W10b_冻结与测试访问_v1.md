# W10b 协议冻结与测试访问 v1

适用于 build-05 的本地 POSIX 文件工作区。冻结解决“这次运行依据哪一版协议、哪份数据和哪次确认”，暴露台账回答“这个课题过去接触过哪些测试集”。二者都不能替代正式划分验收、科研审批或 G3。可从[双课题验收报告](../_交付/2026-11-24-build-05/freeze-final/report.json)复核实际命令。

## 协议冻结

每个课题、协议、版本占用唯一位置 `问题/<problem_id>/协议/<protocol_id>/<version>/freeze.json`。输入为同目录的 `design.json`、本题 `假设.csv` 和 `决策.json`。所有引用沿用工作区相对路径、SHA-256，可带字节数。运行包可以有不同的顶层协议文件名，协议内容及其中的引用必须原样可解析。

| freeze.v1 内容 | 创建与复核规则 |
| --- | --- |
| `problem_id, protocol_id, version, protocol_ref` | 与课题目录及 design-draft.v0.2 草稿对应。草稿和冻结都保持 `formal_use_allowed: false`。 |
| `dataset_ref, split_ref, inputs` | 核实本题快照 ID、划分 ID 以及划分绑定的 `dataset_manifest_sha256`。递归核对 JSON 内的文件引用，包含清单背后的实际数据字节。 |
| `hypotheses, thresholds, threshold_registered_at` | 冻结要求草稿声明的假设与本题本版本登记行相符，含非空陈述、分析计划、UTC 登记时间。草稿的 `decisions.effect_threshold` 必填，允许数值 0，同时保留已填的其他 `*_threshold`。另行登记阈值时，草稿显式提供 `threshold_registered_at`；与假设一起登记时，取关联行最晚的 `registered_at`。 |
| `decision_refs` | 每个引用指向独立确认原件，并在本题决策簿具有相同路径、哈希及非空确认人。拒绝引用其他题卷宗中的原件。卷宗外的同一确认路径也不能被多个课题复用。 |
| `frozen_at, record_sha256` | 工具按实际 UTC 时间生成，支持的命令没有回填冻结时刻的入口。假设与阈值必须已登记。摘要覆盖去掉摘要字段的规范 JSON 编码。 |

`registered_at` 和 `analysis_plan` 对日常卷宗仍为可选列。旧表照常查看；需要冻结时才要求补齐证据。冻结绑定**整份**假设表、决策簿和每个上游输入的字节，追加其他版本的行也会使旧冻结不能再授权新访问。换版请保留旧协议与事件，新版单独冻结。历史暴露仍能独立查询。

`freeze create` 在课题的 `.freeze.lock` 中创建不可覆盖的冻结记录。重复提交同一版本会复核既有内容。`freeze verify` 从当前权威文件重算，任何绑定文件有变化即拒绝。哈希用于本机完整性检查；具有整库写权限者的身份认证、独立可信授时和外部签名未在本轮验收。

## 跨版本测试暴露

课题的 `测试暴露/` 共用一条事件链。每个 `test-exposure.v1` 事件独立落盘，文件名含连续序号和文件内容 SHA-256。事件绑定课题、稳定事件 ID、协议 ID/版本、快照 ID、划分 ID、评价集、实际访问时间与登记时间，并保存当时的输入哈希。`previous_sha256` 引用上一笔。独立文件 `测试暴露.head.json` 保存已发布的链尾。读者先校验整条链，再应用查询条件。

| exposure_kind | 来源与含义 |
| --- | --- |
| `prior_test_exposure` | 已知既往访问，用 `exposure record` 登记。当时的协议、快照和划分必须可辨认，可在冻结前录入。`accessed_at` 填历史时刻，`recorded_at` 为当前登记时刻。重复事件 ID 只允许重送相同内容。 |
| `run_access` | 已声明将访问 `final_test` 的运行。事件 ID 为运行 UUID，绑定其实际 `started_at` 和整份冻结文件的哈希。开始命令在发布运行记录前记账，同步在提交运行前补记异地已开始的运行。相同运行的后续修订、重送及事务恢复共用这一笔。 |

台账只有查询、校验与追加入口，协议版本不参与选择台账文件。`.exposure.lock` 串行化写入，检查链头、链尾与事件序号。事件已持久化而 HEAD 尚未前移时，保留该事件，下一次写入可补齐 HEAD。缺少已锚定事件或旧字节有变即拒绝。若进程在记账后、运行发布前中断，保留这笔可能的访问。一笔访问表示已登记的接触机会；未观察到运行事件的人工访问要单独登记。

以下命令从工作区根执行。将 P、PROTO、V、D、S 替换为对应卷宗的真实编号，实际时间用 UTC 的 `Z` 后缀。

~~~bash
py=/opt/anaconda3/bin/python3
desk=研究管理/工具/research.py
"$py" -B "$desk" freeze create --problem P --protocol PROTO --version V --dry-run
"$py" -B "$desk" freeze verify --problem P --protocol PROTO --version V
"$py" -B "$desk" exposure record --problem P --protocol PROTO --version V --event-id prior-01 --dataset-id D --split-id S --eval-set final_test --accessed-at 2025-01-01T00:00:00Z --dry-run
"$py" -B "$desk" exposure list --problem P --dataset-id D --split-id S --eval-set final_test
"$py" -B "$desk" exposure verify --problem P
~~~

## run.v0.2 与 V07

取值由[词表](词表.json)维护。新包在实验声明中提供非空、无重复的 `eval_sets`，例如 `["dev"]` 或 `["dev","final_test"]`。该字段随预检身份、不可变运行身份和同步索引传递，修订不能增删或改值。配置若也声明评价集，二者须一致。显式声明的预测数据中，W7 的 `rule_dev`、`rule_eval` 对应 `dev`，`heldout_eval` 对应 `final_test`。

原有 v0.2 记录和预检报告仍按原字段读取；缺字段的语义为**历史未声明**。新准入要求声明，仅兼容原有无协议 schema、协议和划分均标有 `fixture_only: true` 的 smoke/exploratory 夹具。确认性运行仍被拒绝。

只要声明包含 `final_test`，预检和同步都按工具所在工作区查本题权威冻结，逐一匹配协议、数据、划分哈希和关联假设。要求 `started_at` **严格晚于** `frozen_at`、阈值登记及所有关联假设登记。时间相等即失败。预检可用实验中的 `started_at` 或 `--started-at` 检查拟开跑时刻，实际开始时重新取本机时间。仅携带一份声明成功的预检报告或另一题的确认无法通过同步。

## V29 运行包静态扫描

预检与同步在解析运行包前检查目录树，覆盖隐藏文件、文件名和未被 manifest 引用的普通文件。扫描分块读取字节，并检查 CSV/TSV 中凭据列的非空值。规则包括 GitHub 令牌、常见服务 API key、AWS access-key ID、Bearer、具名密钥赋值、私钥头和 URL 查询里的 `X-Amz-Signature` / `Signature`。命中或遇到不能检查的路径、链接或特殊文件时拒绝，诊断只返回规则类别。同步在保存引用文件前再检查将写入的字节。

扫描覆盖可识别的明文与常见编码表示。加密、压缩载荷内部、自定义混淆、第三方平台的真实权限与凭据有效性均未验证。预检、查询和所有 `--dry-run` 只读，已有锁可用于协调读取；预览不会创建目录、锁、事件或运行。
