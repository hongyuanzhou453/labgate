# 全文库联查与状态核对契约 v1

适用于 build-06 的本地 POSIX 文件工作区。本契约定义 Q1 文献台账与 `论文内容索引/` 本地全文库之间的只读双向联查、`S15` 课题状态/决策一致性校验，以及统一只读检查入口 `run_checks.py` 的口径与退出约定。所有命令保持 `formal_use_allowed: false`，不替代正式科学评审或 G3 准入。相关工具与门禁可从[统一只读入口](../工具/run_checks.py)与[工作台](../工作台.md)核验。

## 本地全文库只读联查

`工具/literature_index.py` 直接以只读方式接入 `论文内容索引/literature.db`（`schema_version: 2.0.0`）与 `论文内容索引/papers/L*.md` front-matter，只投影核验状态与定量条目计数等元数据，**不复制主卡正文、不读取定量结果数值、也不向 `论文内容索引/` 写入任何字节**。

| 安全与一致性护栏 | 实现规则 |
| --- | --- |
| 只读快照打开 | 禁止路径别名/符号链接；存在 `-wal`、`-shm`、`-journal` 事务旁文件直接拒绝；使用 SQLite 只读 URI（`?mode=ro&immutable=1`）并设置 `PRAGMA query_only=ON`、`trusted_schema=OFF`、`temp_store=MEMORY`；查询完成后复核设备号、inode、字节数与纳秒级 `mtime_ns` 未变化。 |
| 结构与来源校验 | 运行 `PRAGMA quick_check(1)`；校验 `meta.schema_version == '2.0.0'` 及 `inputs_detail_json.ledger` 与 `SRC-LEDGER` 当前 SHA-256 一致；核对 `corpus_inventory`、`papers`、`results`、`concepts`、`paper_concepts` 与 `SRC-LEDGER`、`SRC-ALIASES` 同源版本组无冲突。 |
| 主卡与计数核对 | 逐篇校验 `论文内容索引/papers/L*.md` 字节数、SHA-256、JSON front-matter（`paper_id`、`work_id`、`review_status`、`quantitative_check_status` 与规范化 `title`），并重算 `visual_verified`、`text_verified`、`pending` 行数；标记 `selected_results_verified` 时不得存在 `pending` 行，且主卡集合须与 `papers`、`corpus_inventory(formal_verified)` 完全一致。 |

### 四种检索返回状态边界

| 状态 (`status`) | 触发条件与边界语义 |
| --- | --- |
| `exact_card` | 当前台账编号 `Lxxx` 在全文库拥有精确对应主卡，`has_card: true`，返回 `card_path`、`card_sha256`、`review_status`、`quantitative_check_status`、`result_count`、`verified_result_count`、`result_status_counts` 与 `concepts`。 |
| `related_version_only` | 当前编号本身无精确主卡，但所属 `SRC-ALIASES` 同源版本组（`work_id`）另有一版已建卡；`has_card: false`，精确主卡字段保持 `null`，仅在 `related_card` 中单列同源主卡，**不继承精确计数**。 |
| `not_indexed` | 数据库可用，但当前编号及同源版本组均尚未收录入本地全文库；`has_card: false`，不混淆为“核验为零”。 |
| `unavailable` | `论文内容索引/literature.db` 不存在时返回，保留 `Q1` 台账身份、`local_pdf` 校验与版本组信息，精确主卡数与覆盖计数保持 `null`，**绝不宣称零覆盖**；若数据库文件存在但损坏、缺表或与 `Q1`/主卡身份冲突，则显式失败拒绝，不静默降级。 |

### 联查与健康检查命令

从工作区根目录 `<repo-root>` 使用 `python3 -B` 执行：

~~~bash
py=python3
desk=研究管理/工具/research.py

# 按台账编号反查文献身份、本地全文主卡与各已接入课题的引用上下文（可加 --problem 限定单题）
"$py" -B "$desk" trace L101 --problem demo-selectivity-benchmark --dry-run

# 按课题汇总比较表引用的台账编号（排除项目自身行）、精确主卡覆盖与未收录边界
"$py" -B "$desk" topic-literature demo-selectivity-benchmark --dry-run

# 单独校验本地全文库只读快照完整性与收录统计
"$py" -B "$desk" literature-health --dry-run
"$py" -B 研究管理/工具/literature_index.py --dry-run
~~~

> 约定：改动联查实现后，须在 `论文内容索引/` 目录外验证无 `-wal`/`-shm`/`-journal`/`.tmp` 旁文件生成，并重跑 `论文内容索引/build_index.py --check` 与 `论文内容索引/build_db.py --check`。

## S15 状态、假设与决策一致性规则

`工具/topics.py` 与 `工具/check_all.py`（`V19.state`）共同校验课题卷宗内部的一致性，不填补或篡改未确认科研选择：

1. **决策登记簿（`决策.json` · `decisions.v1`）**：
   - 兼容 W10b 仅确认行（不含 `decision_id`）与逐项决定行（含 `decision_id`、`statement`、`basis`、`YYYY-MM-DD` 格式 `date`，可选 `protocol_id/version`、`hypothesis_id/version` 及非 `null` 的 `decision_key/value`）。
   - 每条登记须含非空 `confirmed_by` 与外置人工确认原件 `confirmation_ref`（工作区相对路径 + 完整 SHA-256），不得指向卷宗保留文件、`协议/`、`测试暴露/`、`_交付/` 或兄弟课题目录；同一卷宗外确认文件路径不得被多个课题重复登记。
2. **状态文件（`状态.md`）九节与引用格式**：
   - 必须严格包含 9 个既定小节且均非空（`当前判断`、`支持证据`、`反对证据`、`资源缺口`、`实验草案`、`决策记录`、`需领域确认`、`待决定`、`下一步`）。
   - 未否定或未待决的肯定决定措辞（如已确认/已批准/选定采用等）不得散落于正文；所有已确认决定必须放在 `## 决策记录` 节，逐行精确匹配：
     `- [决策 <decision_id>] YYYY-MM-DD | <statement> | 依据=<basis> | 确认人=<confirmed_by>`，且逐字段与 `决策.json` 双向核对。
   - 若 `状态.md` 引用本地全文主卡，仅允许在 `## 支持证据` 或 `## 反对证据` 小节独占一行写 `- [主卡 Lxxx] 已核验` 或 `- [主卡 Lxxx] 待审`（禁止直接在正文内书写 `论文内容索引/papers/L*.md` 路径逃避核查）。`check_all.py` 的 `V19.state` 会联网外只读核对所引编号确为 `exact_card`，且标注 `已核验` 时必须满足 `review_status == 'full_text_reviewed'`、`quantitative_check_status == 'selected_results_verified'` 与 `verified_result_count > 0`。
3. **协议草稿与假设双向绑定**：
   - `design.json` 的 `notes`/`note` 不得夹带未登记到 `decisions` 的肯定决定；草稿中任一非 `null` 的 `decisions.<key>` 须在本题同协议版本的已登记确认中找到完全相同 `decision_key` 与 JSON 编码等价的值（区分数值 `0` 与布尔 `false`）。
   - `假设.csv` 或 `design.json` 中状态为 `confirmed`/`approved`/`已确认`/`已批准` 的假设必须提供已登记的 `decision_ref`，并校验其协议版本与假设版本作用域。

## 统一只读校验入口 (`run_checks.py`)

`研究管理/工具/run_checks.py` 为纯只读总控调度入口，始终向所有子命令传递 `--dry-run`，逐项保留命令、退出码与解析后的 JSON 输出：

~~~bash
# 仅跑工程门禁、工作台新鲜度、周报完整性与全文库只读健康检查（全部通过返回退出码 0）
python3 -B 研究管理/工具/run_checks.py --stage G2 --runtime-report 研究管理/_交付/demo-baseline/runtime-final/report.json --literature

# 含按题 G3 全量汇总（当前因示例科研决定与划分缺失返回退出码 1，同时完整保留其余 pass 子项）
python3 -B 研究管理/工具/run_checks.py --stage all --problem demo-selectivity-benchmark --runtime-report 研究管理/_交付/demo-baseline/runtime-final/report.json --literature --dry-run
~~~

- `--stage {G1,G2,G3,all}`：默认 `all`；`--problem` 仅在包含 `G3` 时允许指定；`--baseline` 透传给 `check_all.py`；`--literature` 追加执行 `research.py literature-health --dry-run`。
- 任一子检查超时（120 秒）、输出非规范 `pass/fail` JSON、退出码与 JSON 状态自相矛盾、或返回非零退出码时，该子项判为 `fail` 且汇总整体返回退出码 `1`。
