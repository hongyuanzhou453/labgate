# W7 候选划分验算：严格双侧 Kd 固定面板

`check_split.py` 是只读检查器，适用于一个固定 T/O 构建体组合、无最终系列支持标签、来源测量只用于 `base_fit` 的子方案。它消费已经准备好的候选，**不分配角色、不读取标签数值作选择、不发布划分**。示例见[完整合成包](../_交付/2026-11-18-build-02/split-01/legal_rotation_shared_panel/receipt.json)。

## 三个独立指定的输入

| 命令参数 | 内容与职责 |
| --- | --- |
| `--dataset` | `candidate-universe.v1`。完整 `dataset_id=D-<UUID4>`、`grouping_scheme`、每来源的 `source_data_refs`（底层数据字节）和 `pools`（逐测量名单）、`grouping_ref`、`eligibility_ref`。把源名单和资格作为独立基准，不能从被验成员表反推。 |
| `--policy` | `candidate-policy.v1`。绑定同一数据 ID、`dataset_manifest_sha256` 和同一分组方案，声明 `profile=fixed-panel-strict-paired.v1`、`fold_ids`、`origin_scopes` 全集、`panel_origin`、不同的 `target_construct_id/offtarget_construct_id`、`endpoint=strict_kd_point`、`allowed_shared_entities=["construct_id"]`、`support_policy=none`。研究者选择真实策略；本轮只有合成示例。 |
| `--split` | `candidate-split.v1`。`split_id=S-<UUID4>`、`dataset_id`、`dataset_manifest_sha256`、`policy_sha256`、`files.members`、`files.pairs`、`pairs_from_members_sha256`、`counts`。三个文件均要求 `formal_use_allowed=false`。 |

每个文件引用含相对于**所属 manifest 目录**的 `path`、实算 `sha256,bytes`。CSV 引用另带 `record_count`，不含表头；表头按列名解析，必须与本版字段匹配。输入数据/角色方案必须由调用者独立指定，不能只相信被验划分自报的“零泄漏”或它提供的唯一数据来源。

| 表 | 字段 | 关键约束 |
| --- | --- | --- |
| 每个源的名单 | `measurement_id,compound_id,construct_id,observation_id,endpoint` | 每条测量 ID 全局唯一；重用/转载同一次原始观测须共享逐观测 `observation_id`，不能用整库 `lineage_id` 代替。单折不能把两版本同时计入。 |
| 分组映射 | `origin_scope,compound_id,local_group_id,joint_group_id,overlap_key` | 所有源配体均须覆盖；一个来源内每配体唯一，可另含未被测量的桥接配体。局部分组只在源内同名相通，联合组和预定的重叠键跨源相通。重叠键用于保守隔离，不是实验证明两个样品相同。 |
| 用途资格 | `measurement_id,intended_use,decision` | 每条测量每种用途唯一；实际使用须对**该用途**有 `include`。`pending`、`exclude`、缺行均不放行。已有诊断视图不能直接作为训练资格输入。 |
| 成员 | `split_id,fold_id,measurement_id,compound_id,construct_id,group_id,role,label_access,intended_use,origin_scope,exclusion_reason` | 每折对全体源测量逐一给出角色，`group_id` 必须等于该来源映射中的联合组。排除写 `role=excluded, label_access=none, intended_use=none` 和非空理由；缺行不是排除。 |
| 配对 | `split_id,fold_id,pair_id,role,t_measurement_id,o_measurement_id` | 同折的 `pair_id` 唯一；须与从角色成员推导的完整 T/O 对集合逐项相等。来源成员不参与面板差值。本版不合并重复实测。 |

## 实际检查的内容

1. 数据字节、成员、配对、独立策略及资格/系列文件须与内容引用一致。每一折均须覆盖每一个来源的所有已登记测量；一个来源或一条测量都不能从候选表中悄悄消失。
2. 从分组表建立连通关系：相同配体、同源局部组、跨源联合组、跨源重叠键。即使一端为另一蛋白的供体，中间配体没有测量，仍须隔离整个连通组。组是防泄漏边界，不是已证实的独立 SAR 系列。
3. 每折面板包含四种非空角色。`base_fit` 用 `point_training/fit`，`rule_dev` 用 `point_training/develop`，`rule_eval` 用 `point_evaluation/evaluate`，`heldout_eval` 用 `point_evaluation/sealed`。面板以外的来源/蛋白若使用，只能以 `source_pool/fit` 进入 `base_fit`。同组不能在同折跨活动角色；开发角色允许换折，最终留出的测量集合在各折完全相同。
4. 先由**当折、同角色、同配体**的两侧目标测量导出应有的有向配对，再核对实际配对；拒绝缺边、错边、倒置和重复。`pairs_from_members_sha256` 绑定成员版本。此项验证产物依赖与集合一致，不是生成时序或标签从未泄露的证明。
5. 逐折实算角色计数、活动配体、活动连通组、供体测量和配对数，再核总输入测量、跨折成员行及配对行；与 `counts` 严格比较。折数、配对数都不是独立样本量。

## 仍需的证据

通过只表示**给定这份独立名单、分组和策略**后，候选结构一致。源名单是否忠实覆盖真实数据、逐观测别名是否正确、代理分组是否有科研意义、未见测试标签是否在实际存储中受控，均要另证。本工具校验原始数据字节，不把其内容自动转换为可用标签。它也不实现收益标签的开发内折外估计、few-shot 支持集、正式数据导出/冻结、实耗预算或统计精度。正式实验仍受 G3 约束。
